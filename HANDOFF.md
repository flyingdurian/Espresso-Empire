## What changed in Pass 2

- **Espresso controls:** `touch-layout.ts` now provides `shotKeyTouch()` and `portafilterTouch()`; `main.ts` feeds desktop boxes and compact CSS variables from these shared helpers. The compact Short key top is 41.8%, Standard top 47.3%, both 5% stage height. Standard ends at logical Y 492.143; grip starts at Y 501. Separation is 8.857 logical units (~3.13 CSS px at a nominal 333 px stage height). Short/Standard gap is 4.705 logical units (~1.67 CSS px). CSS removes the old 19 px minimum-height and negative offset for shot keys in compact mode. Desktop key positions remain unchanged. All groups, pull types, pitchers, and portafilter service mechanics are unchanged. Compact key height is ~16.65 CSS px, a tradeoff to achieve exclusive ownership. The preexisting Short/grinder proximity and very small pitcher targets still deserve device checks.
- **Reserve ownership:** `shotPocketTouch()` and `foodWellTouch()` inset each cell by 2 logical units on each edge (4-unit/1.42 CSS px gaps between cells); `shotRackBezelTouch()` confines the generic first-free rack shortcut to the outer perimeter rather than internal gaps. `chooseShotPocket()` in `service-pass.ts` is used by `main.ts` for exact taps and drops: an explicitly requested occupied or transfer-reserved pocket is rejected, never redirected. The player retains their picked source and receives a prompt. The intentional rack-wide first-free shortcut and food-category first-free deposits remain available. Retrieval still selects the individual indexed portion. Rack capacities 8/4/3, all P1 rack positions, seat/art anchors, and gameplay inventory logic are unchanged. The gutters reduce target dimensions; shot cells are ~11.6 x 10 CSS px and middle pastry cells ~30.7 x 6.7 CSS px at nominal scale. This is a precision tradeoff, not a claim of comfortable touch sizing. Outer perimeter shortcuts are narrow. Test retrieval and shortcut discoverability on device; a larger reserve interaction view may still be needed.
- **Appliances and supplies:** `applianceTouch()` defines independent slots with at least 6 logical units (~2.12 CSS px) between adjacent racks/plates in both front and rear. Whole-machine shortcuts remain on the outer bezel, not the slot band or its neutral internal gaps; direct slot drops still require the P1 state-aware eligibility checks. Neutral-space assisted drops still follow the P1 nearest-usable rule and may resolve to a single nearby valid destination. Front supply bins already clear the front oven and press; their hit width is now 86 units (8 units between bins), and the cornetto hitbox bottom is clipped 4 units above the fridge. Rear cornetto and panini supply centers move from Y 616 to Y 650 in `rear-layout.ts`, which is also consumed by `rear-kitchen.ts` for rendering and flight origins. Their top is Y 603, leaving 10/17 logical units (~3.5/6 CSS px) below oven/press. No art file, slot count, or appliance timer changed. Inspect actual painted alignment on device.
- **Gesture ownership:** `gesture-ownership.ts` defines interactive-origin exclusion and pointer-ID cancellation. `counter-travel.ts` only starts a swipe on neutral space; all equipment buttons (including non-carry, disabled, nested control contents, guest/other destinations), form controls and aside/dialog are excluded. An existing pointer cannot be replaced by another primary pointer. Secondary leave/cancel events cannot terminate the active turn; lost capture cancels the owner without committing. `main.ts` accepts only primary item starts, gates item `pointercancel` and `lostpointercapture` by owner ID, and applies matching cancellation ownership to the header area strip; window blur still deliberately resets item/travel. Existing movement thresholds, cup inspection, and P1 drop resolution remain unchanged. Native click delivery and multitouch behavior still require a real Safari check.
- **Tests:** `tests/p2-controls.test.ts` adds 9 focused cases for desktop/compact key separation, reserve spacing and strict specific-pocket selection, slot/bezel/supply geometry, real travel listener behavior in a minimal event fixture, and owner-specific cancellation integration. The 11 P1 tests remain unchanged. Tests exercise shared helpers and real travel handler callbacks, not browser CSS layout or physical touch. `src/counter/bench.ts`, `drop-target.ts`, `drop-eligibility.ts`, `station-layout.ts`, all public files, all existing tests and `scripts/read.ts` are byte-identical to P1. No configuration or asset bytes changed in P2.

## What changed in Pass 1

- `src/counter/drop-target.ts`: nearest actionable control owns the release. A directly hit incompatible, disabled, or unusable control blocks proximity fallback. Only neutral space within the world can snap; candidates must be usable, visible/enabled, and within the visible stage bounds. The original 12 CSS px touch radius and mouse exact-only behavior are retained. Distinct destinations within 0.5 CSS px of the nearest distance cancel rather than select by DOM order; multiple controls representing the same destination (e.g., guest body and ticket) are treated as one semantic destination. `bin` remains exact-hit-only.
- `src/counter/drop-eligibility.ts`, `bench.ts`: read-only eligibility checks for source stock, cup occupancy/lids, directed pour queue, ready pitchers, reserve pockets, guest matches, appliance slots, food wells, cup return, waste capacity, and portafilter/tamper/beans states. `Bench.canDropPour` mirrors existing immediate and queued `dropPour` guards; the authoritative `Bench.command` implementation and gameplay rules are unchanged. The UI uses the same preflight for pointer movement and release. An invalid specific shot-pocket drag cancels rather than falling back to another pocket. P1 left tap-to-stage fallback unchanged; P2 also rejects invalid specific taps. Generic rack/category well first-free behavior remains available. A queued pour is accepted according to the existing queue rule, not a guarantee of later success if inventory changes.
- `station-layout.ts`, `touch-layout.ts`, `main.ts`, `style.css`: shared logical hitboxes; milk lane center spacing 40 -> 55 logical units, target widths 45, plus vertical gaps between steam, pitcher and pour controls. Mobile minimum heights and negative margins no longer enlarge milk hitboxes into neighboring controls. Five syrup centers are 1441/1492/1543/1594/1645 (51 apart), target widths 42 (9 logical units gap). Renderer and pour animation already consume the shared anchors; original artwork files are unchanged.
- `public/data/service-pass.json`, `service-pass.ts`, `touch-layout.ts`: shot rack X 505 -> 480; panini X 877 -> 903 and pastry X 1008 -> 1034 to remove saucer intrusion. Front food staging baseline Y 587 -> 718, with 82 x 44 hitboxes centered at Y 700. This moves the rendered plate/food and associated animation anchor with the interactive region. Rear kitchen was unchanged in P1; P2 relocates its supply bins. All eight shot pockets, four panini wells, three pastry wells, two towel spaces and two saucers remain available. At the nominal 592 x 333 rendered world, the milk gap is about 3.5 CSS px, syrup gap 3.2 px, rack/saucer gap 3.0 px, and minimum towel/empty-saucer gap about 1.1 px. These are source-derived estimates, not measurements on Safari; controls are still small.
- `tests/touch-layout.test.ts`: 11 tests for exact ownership, neutral proximity, disabled/hidden candidates, clipped bounds, ties, destructive exact hit, exclusive milk and syrup geometry, reserve/towel vs every configured cup, directed pours, reserve staging, stateful appliance/cup/food/bin validity and guest readiness. DOM contract tests use a minimal fixture, not a browser. Geometry helpers are the same ones consumed by `main.ts`.

No changes to recipes, inventory capacities, authored asset bytes, shift data, equipment timers, guest scripts, or hosted site metadata in either pass. Only layout X/Y values in `service-pass.json` changed in P1; no public file changed in P2. `README.md` and review images are historical.
